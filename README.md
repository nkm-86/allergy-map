# allergy-map
アレルギー情報を掲載している飲食店を一覧やマップで検索できるWebサイト。

検索仕様 v3：選択した品目について、公式資料の記載を確認できる店舗を探します。アレルゲン不使用や安全性を判定するものではありません。

PHP 8以降とPDO（SQLiteまたはMySQL）が必要です。正式な画面は `index.php`・`map.php`・`detail.php` です。HTML版はPHP版へ転送します。

DBは環境変数 `DB_DRIVER=sqlite`（既定）または `DB_DRIVER=mysql` で明示的に選択します。接続失敗時の別DBへの切り替えや、画面アクセス時のDB初期化は行いません。設定項目は `.env.example` を参照してください。このファイルを自動読込する仕組みはありません。

既存DBの移行コマンド：

```sh
php database/migrations/001_official_sources.php
```

既存のrestaurantsテーブルを対象とします。破壊的な `sql/allergy_map.sql` を移行目的で実行しないでください。コマンドは最初に `storage/backups/` へバックアップを作り、旧カラム・店舗IDを維持して地域・座標・情報源テーブルを追加します。再実行で情報源は重複せず、既存の確認状態も上書きしません。SQLiteバックアップはDB全体、MySQLは全テーブルのスキーマとデータをJSONで保存します。MySQLのDDLは暗黙コミットされるため、保守時間中に実行してください。

移行したURLは `pending`、品目は `not_confirmed`、座標はNULLです。公式資料を実際に確認してから、情報源を `verified`、各品目を `published` にして、それぞれの `checked_at` を登録します。`not_applicable` は対象外と確認した場合にだけ登録します。移行前の `allergy_codes` は検索に使用しません。既存データの照合期間中は旧カラムを残します。

一覧と地図は同じ検索処理を使います。複数品目の指定はAND条件、キーワードは店舗名と住所だけを対象とします。情報源・品目の両方に確認日があるものを確認済みとして扱います。座標がNULLの店舗は一覧には表示し、地図には表示しません。

検証コマンド：

```sh
php tests/search.php
```

開発用起動例：`php -S 127.0.0.1:8791`。開発サーバーでは公開範囲を制限し、外部へ公開しないでください。Apache用に `app/`・`database/`・`storage/`・`sql/` のアクセス拒否を設定しています。Nginx等では同等の拒否設定が必要です。`public/`へのディレクトリ分離、管理画面・審査機能、公式資料の内容確認、正確な座標登録は後続作業です。MySQLでの移行・ブラウザ表示は別途実環境で検証してください。
